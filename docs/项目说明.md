# 项目说明

> 这份文档假设你**没接触过电力系统**。第一节用类比把核心概念讲清楚，
> 后面才是技术细节。已经懂的人可以直接跳到第 3 节。

---

## 1. 先看懂这几个词

### 1.1 用自来水打个比方

配电网和自来水管网几乎是一一对应的：

| 电力 | 自来水 | 说明 |
|---|---|---|
| 变电站 | 水厂 | 电/水的来源 |
| 馈线 | 主干水管 | 从源头送到各家各户的那条线 |
| **电压** | **水压** | 压力够不够，用户能不能正常用 |
| **潮流** | **水流** | 水/电从哪流到哪、流多少 |
| **网损** | **管路摩擦损耗** | 输送途中白白损失掉的部分 |
| 负荷 | 用户用水 | 大家用掉的部分 |

这样一来，本项目要研究的问题就变得很好理解了：

> **光伏 = 有些用户在自家院子里打了口井。**
> 井水多了，不但够自己用，还会**倒灌回主管道**。
>
> 倒灌会带来两个麻烦：
> 1. **倒灌的水会在管子里来回冲，摩擦损耗反而变大**（网损先降后升）
> 2. **倒灌会把管道压力顶高**，压力太高管子会爆（**电压越上限**）

**本项目就是在算：这条管道最多能容纳多少口井，才不出问题。**

### 1.2 几个必须知道的词

**标幺值（p.u.）** —— 电力行业的习惯：不用绝对值，用"**占额定的百分之多少**"来表示。
比如电压 1.0 p.u. 就是"正好等于额定电压"，0.95 p.u. 就是"只有额定的 95%"。
好处是不同电压等级的电网可以用同一套数字描述。

**无功 / 功率因数** —— 电分两种：**有功**是真干活（让电机转、灯泡亮），
**无功**是在电感和电容之间来回倒腾、不干活但占着管道的"虚功"。
两者合起来才是电线实际要承受的总量。光伏逆变器可以只出有功不出无功（叫"单位功率因数"）。

**渗透率** —— 本项目最常用的一个词：

```
渗透率 = 光伏装机容量 ÷ 馈线总负荷 × 100%
```

100% 就是"光伏装机刚好等于大家的用电量"。**但装机不等于实际出力** ——
光伏典型日的峰值出力只有装机的 ~70%（云、日照角、温度都会打折），
所以 100% 渗透率的实际峰值出力大约只相当于 70% 的负荷。

**弃光** —— 光伏明明能发，但被**主动削减**了。原因通常是电网接不住
（电压会超限、或者不允许倒送）。相当于井水太多、管子受不了，只好放掉一部分。

**切负荷** —— 反过来，电不够用的时候**主动断掉一部分用户**。这在模型里是"最后兜底手段"，
代价极高（用专业术语叫 VOLL，失负荷价值）。相当于水不够了，只好关掉一部分用户的水阀。

**储能（SOC）** —— 电池。SOC 就是"电量百分比"。
它的价值在于**时间搬移**：中午光伏多的时候充进去，傍晚光伏没了再放出来。

## 2. 这个项目解决什么问题

### 2.1 出发点

光伏出力的**预测**现在已经能做得很准了（用机器学习），但预测本身不产生价值 ——
价值在于**拿它去做决策**。

这个项目要补的就是这一段：把概率预测接进微电网的优化调度，回答一个具体问题：

> **一条给定的配电馈线，究竟能接纳多少光伏？瓶颈在哪里？**

### 2.2 为什么这个问题不能靠"经验"回答

因为答案完全取决于**你看哪个约束**。本项目实测的一个结果最能说明这点：

同一条馈线，如果按**热容量**（电线会不会烧）算，承载力有 **238%**；
按**电压上限**算，只有 **172%** —— 差了 38%。

更关键的是，如果电压上限取行业里常见的宽松值 1.10，这个数字会变成 **245%**，
**比按配电网实际标准（1.05）算出来的高估 43%**。

**同一套数据，同一个模型，只是换了个电压限值，结论就差近一半。**

所以项目的主线是：**把各种约束摆到同一套模型里逐一定量，并确保每个结论都经得起真实物理的检验。**

## 3. 系统架构

### 3.1 一个绕不开的矛盾

电力系统里有个根本矛盾：

> **能快速求解的简化模型，都看不见电压；能算准电压的模型，都慢得没法做优化。**

- 直流潮流、线性化潮流 → 快，能塞进优化求解器，但**电压被当成恒等于 1.0**
- 全交流潮流 → 准确，但非线性，直接做优化非常慢

这个矛盾不解决，优化结论就不可信。本项目的处理是：

**不假装解决它，而是把它量出来。**

```
     ┌─────────────────────┐
     │   简化模型（可解）   │   ← 优化在这里做
     │  DC / LinDistFlow   │      因为它线性、快
     └──────────┬──────────┘
                │ 解
                ▼
     ┌─────────────────────┐
     │  MATPOWER 全交流潮流 │   ← 真值在这里
     └──────────┬──────────┘
                │
                ▼
      两者差多少、差在哪个方向 = 可量化的误差
```

**一句话总结这个原则：简化模型负责优化，全交流潮流负责说真话。**

### 3.2 三层结构

| 层 | 干什么 | 在哪 |
|---|---|---|
| ① 数据层 | 光伏概率预测 → 优化能用的输入曲线 | `bridge/`（Python） |
| ② 优化层 | 潮流、调度、时序、鲁棒优化 | `src/` + MATPOWER + MOST |
| ③ 校验层 | 用全交流潮流逐时段验证优化解 | MATPOWER `runpf` |

## 4. MATPOWER 在这里是干什么的

这一节单独讲，因为这是整个项目里最容易被误解的部分。

### 4.1 一句话

**MATPOWER 不是"被研究的算法"，而是"物理真值的唯一来源"。**

它不是题目，是**标尺**。项目里所有优化模型的解，最后都要拿它量一遍。

### 4.2 用到了 MATPOWER 的哪些组件

| 组件 | 在本项目中的用途 |
|---|---|
| **`runpf`**（交流潮流） | ★ **贯穿全程的真值校验**：渗透率扫描、重构评估、以及每个优化解的回灌检验 |
| **`runopf`**（交流最优潮流） | 单时段经济调度；与直流模型对比，暴露"直流看不见电压"这件事 |
| **`case33mg` / `case33bw`** | 算例来源。`case33mg` 自带 5 个常开联络开关 —— 正是"配电网 ↔ 微电网"的开关 |
| **`most`**（多时段调度工具） | 24 小时时序调度。储能的电量是跨时段耦合的，单时段模型表达不了 |
| **`makeYbus` / `makeBdc`** | 底层网络模型（交流导纳阵 / 直流系数阵） |
| **`order_radial`** | 重构后的"辐射性"检查（拓扑是否合法） |
| **`mpoption`** | 求解器与输出选项 |

### 4.3 核心作用：真值校验器

这是最值得讲清楚的部分，看一个具体例子。

**场景：24 小时调度**

1. 用 MOST 求 24 小时的最优调度。但 **MOST 只支持直流模型** ——
   它的说明文档原话是 *"当前实现限于直流潮流建模"*。
   **直流模型里电压恒等于 1.0，所以 MOST 根本看不见电压约束。**
2. MOST 给出一个它认为最优的调度，成本 1358.62 美元/天。
3. 把这个调度**逐时段灌回 `runpf`**（全交流潮流）重新算一遍。
4. 结果：**19 点到 22 点这 4 个时段，最低电压跌到 0.8933，越过了 0.90 的下限。**

MOST 对此一无所知，会认为自己的解既最优又可行。**是 MATPOWER 的交流潮流戳穿的。**

这个模式在项目里出现了三次：

| 阶段 | 简化模型说 | MATPOWER 交流潮流说 |
|---|---|---|
| P4 | MOST：全程可行 | 4 个时段电压越下限 |
| P5 | 线性化模型：最低电压 0.8982，0 处越限 | 最低电压 0.8940，7 个时段越下限 |
| P5 | 线性化模型：从电网买电 62.03 MWh | 66.05 MWh（差的 4.02 就是网损） |

而且**误差有明确的方向**：线性化模型忽略了线路损耗 → 算出来的压降偏小 →
电压偏高 → **系统性地对"欠压"乐观**。

也就是说，优化器会**以为自己没违规，实际已经违规了**。这个方向性偏差正是必须靠
交流潮流校验兜住的东西。

### 4.4 反过来，MATPOWER 本身也是被审视的对象

项目不只把 MATPOWER 当标尺，也记录了它的边界和使用中踩到的坑（对使用者有用）：

- **MOST 的直流限制**：多时段调度看不见电压，架构上必须绕
- **分时电价走不通**：想通过改发电成本曲线实现分时电价，实测不生效
  （把价格乘数设成 3 倍，目标值都不变），最后改成直接改二次成本曲线
- **`case33mg` 的爬坡率全为 0**：单时段无所谓，但多时段调度直接不可行 ——
  机组在一个时段内完全无法调整出力，而负荷在变。MOST 只报一句
  "数值失败"，不告诉你原因
- **`loadmd` 数 profile 个数的方式很坑**：它用矩阵的**行数**来数，
  拼成行向量就会只处理第一个、其余静默丢弃
- **`RATE_A = 0`**：`case33mg` 原始算例没有任何支路容量约束，
  直流模型下永远看不到"线路过载"

### 5.1 数据侧

|---|---|

| 交流潮流 / 直流潮流 / 最优潮流 | MATPOWER 原生 |

| **配电网重构**：搜索网损最小的接线方式 | `src/reconfigure.m` |
| **微电网环网运行**：穷举联络开关组合，量化合环收益 | `src/reconfigure.m` |
| **单时段经济调度 + 弃光分析** | `src/run_ed.m` |
| **24 小时时序调度**（含储能电量） | `src/run_most_24h.m` |
| **简化模型 vs 交流潮流的精度对标** | `src/test_p5_distflow.m`、`src/validate_dispatch_ac.m` |
| **分布鲁棒优化**：场景生成 / 模糊集 / 样本外评估 | `src/dro_24h.m` |

### 5.3 分析产出

- 各约束的触发渗透率（把"承载力"拆解到每个约束）
- 电压限值选择的敏感性（1.05 vs 1.10 差 43%）
- 网损随渗透率的变化曲线及最低点
- 重构的收敛轨迹与最优接线方式
- 时序调度的储能电量轨迹与弃光量
- 简化模型与交流真值的误差**大小与方向**
- 三种决策策略的样本外成本分布、尾部风险、越限率

## 9. 结论速查

### 9.1 承载力分解（电压上限取配电网实际的 1.05）

| 发生了什么 | 渗透率 |
|---|---|
| 最低电压达标 0.95（治好了基态就有的欠压） | **56.5%** |
| 网损最低（89.6 kW，比基态降 58%） | 80% |
| 变电站从"送电"变成"受电"（开始倒送） | 102.7% |
| **电压越过上限 1.05** | **171.8%** |
| 支路过载（热容量） | 237.7% |
| （对比）电压上限若取 1.10 | 244.9% |

### 9.2 三条核心结论

1. **瓶颈是电压，不是热容量。**
   支路负载率全程最高才 108%，而电压在 172% 就顶到上限了。

2. **电压限值的取值直接决定结论。**
   1.05 与 1.10 让承载力差 **43%**。用宽松值会严重高估。

3. **弃光的主因是"禁止反送"，不是电压。**
   交流最优潮流里，光伏出力饱和在 3.814 MW
   （= 负荷 3.715 + 网损 0.099），此时电压才 0.995，离上限远得很。

### 9.3 一个否定结果

分布鲁棒优化（考虑"预测本身可能不准"）与普通随机优化、甚至只用中位数预测的
确定性方法相比，**样本外表现差异小于 0.15%**（换用 IEEE RTS-79 负荷曲线后重跑，
结论不变：三种策略的期望成本分别是 1280.3 / 1280.5 / 1280.5 美元/天）。

机制是对的（鲁棒半径从 0.05 加到 1.0，场景间成本离散度从 92.5 单调收缩到 0），
但**收益可忽略**。原因是储能杠杆太小（3 MWh 对 89 MWh/天的负荷）、
不确定性温和（光伏日电量只波动 ±12%）。

**结论：这个系统不需要鲁棒优化。** 这是系统的性质，不是方法的问题。

> **顺带发现（换负荷曲线带来的）**：负荷曲线的**峰均比**决定变电站容量上限会不会成为瓶颈。
> 原来那条合成曲线峰均比 1.44，会顶到 4.2 MW 的变电站上限，产生 0.857 MWh 切负荷；
> 换成 RTS-79 冬季（峰均比 1.20）后切负荷降到 **0**。
> 这提醒我们：**负荷曲线的形状不只是"好看"，它会直接决定哪个约束先出问题。**

### 9.4 光伏节点空间相关性的影响

原来假设"一片云同时盖住全部 4 个光伏节点"（ρ=1），物理上不成立。现已加入相关系数
ρ（高斯 Copula 构造，保证边缘分布不变），并实测了四个取值：

| ρ | 节点间实测相关 | 总出力波动 ÷ 单节点 | E[成本] $/d | **CVaR95** | **最坏** | DRO−SAA |
|---|---|---|---|---|---|---|
| 1.0 | 1.000 | 4.00 | 1280.5 | **1303.9** | **1310.6** | +0.000% |
| 0.8 | 0.790 | 3.67 | 1280.9 | 1298.7 | 1310.3 | +0.000% |
| 0.5 | 0.489 | 3.14 | 1280.7 | 1296.3 | 1305.7 | +0.000% |
| 0.0 | −0.004 | **1.99** | 1280.8 | **1292.1** | **1296.0** | +0.007% |

**两个结论：**

1. **空间解耦确实降低尾部风险**（分散化效应是真的）：CVaR95 降 **0.9%**、
   最坏成本降 **1.1%**。总出力波动从 4 倍降到 2 倍（与理论值 4.0 / 2.0 完全吻合）。
2. **但不改变"不需要 DRO"这个结论** —— 三种策略的差异仍然 ≈ 0。
   **说明否定结果是稳健的，不是空间相关假设造成的假象。**

期望成本几乎不变（1280.5 ~ 1280.9），说明 ρ 主要影响**尾部**而不是均值 ——
这符合直觉：分散化不改变平均出力，只让极端情形变温和。

## 11. 术语表

| 术语 | 大白话解释 |
|---|---|
| **标幺值 (p.u.)** | 用"占额定的百分之多少"表示，1.0 = 额定值 |
| **馈线** | 从变电站送到用户的那条主干线路 |
| **潮流** | 电在电网里怎么流、流多少 |
| **网损** | 输送途中白白损失的电（发热） |
| **有功 / 无功** | 有功是"真干活"的电，无功是来回倒腾、不干活但占容量的电 |
| **功率因数** | 有功占总容量的比例。=1 时全是有效功 |
| **渗透率** | 光伏装机 ÷ 馈线总负荷 |
| **弃光** | 光伏能发但被主动削减的部分 |
| **切负荷** | 电不够时主动断掉部分用户（代价极高） |
| **VOLL** | 失负荷价值，切负荷的惩罚单价 |
| **SOC** | 电池剩余电量百分比 |
| **直流潮流** | 简化潮流：忽略电阻和无功，电压恒为 1.0。快但看不见电压 |
| **交流潮流** | 完整非线性潮流。本项目的"物理真值" |
| **线性化潮流 (LinDistFlow)** | 把交流潮流在电压上做线性化，牺牲精度换速度 |
| **最优潮流 (OPF)** | 在电网约束下求最省钱的发电方案 |
| **重构** | 改变配电网的开关状态，换一种接线方式 |
| **辐射状** | 配电网的树状结构（不存在环路） |
| **线性规划 (LP)** | 目标函数和约束都是线性的优化问题，有成熟求解器 |
| **鲁棒优化 (DRO)** | 承认"我对未来的预测本身不准"，在"可能分布的集合"里取最坏情况来决策 |
| **Wasserstein 距离** | 衡量两个概率分布差多少的指标 |
| **CVaR** | 条件风险价值：最差的 α 比例场景的平均值，用来衡量尾部风险 |
| **场景 (scenario)** | 未来的一种可能实现，比如"光伏今天偏少" |
| **样本外评估** | 用**没参与训练**的数据测试，检验是否真的有效 |
| **ANSI C84.1** | 美国配电电压标准，允许 ±5% |
| **MOST** | MATPOWER 的多时段调度工具（仅支持直流） |
